# WorkBuddy 的 ERP 匹配和试剂库处理

Web UI 使用现有的 WorkBuddy 批次循环入口，ERP 写入后端选择已验证的接口写入。

- 正式运行准备新批前，先执行整张清单的一键匹配，回读后只将类别仍为空的记录发送给 WorkBuddy。测试模式只读。
- 写入模式“仅保存”保持只填写、保存类别；“保存并生成试剂库”在类别保存并回读成功后，再调用 ERP 的明细生成试剂库接口。
- 新建须回读确认新记录和类别；ERP 明确返回“已存在、没有修改项”记为无需修改。ERP 要求确认修改已有库记录时停止，不自动覆盖。
- 类别保存与入库结果分别记录在批次 state.json，并写入审计日志。入库未完成时保留 result.xlsx、停止循环，避免类别保存被误报为失败后重复保存。
- 接口结果不明或报错时不自动重复入库。先核对 ERP 及批次状态；不能通过删除检查点或重新建批代替核对。
- 这两项操作不点击审批清单的“通过”。

## 候选优化与发布条件

- `workbuddy.compact_rules` 为 `false` 时沿用 XLSX 读取。开启后，已审阅规则的发布同时生成带源 SHA-256 的紧凑缓存。正式 XLSX 仍是规则源。每段 UTF-8 文本最多 12,000 字节。批次复制并校验分段，发送前缺失或损坏时回退本批 XLSX。发送后发现文件被修改时暂停导入。
- `workbuddy.reuse_chat` 为 `false` 时逐批新开任务。开启后，已完成批次的规则版本、读取格式及原对话均可确认时，允许继续第二、三批，第四批新开任务。发送结果不明时核对原批次，保留既有恢复记录。
- `workbuddy.freeze_web_todo_scope` 为 `false` 时 Web UI 全量任务每轮查询 ERP。开启后首次查询固定范围。钉钉全量任务已有此行为，指定清单按原选择运行。
- 开关均默认关闭。只在隔离桌面通过同模型对照、三批续聊和第四批切换后并入。隔离项目和后续正式验证使用 `WORKBUDDY_PROJECT_INSTRUCTIONS.txt` 中更新的项目指令。同一会话连续三批和第四批切换使用隔离 Web UI、真实 WorkBuddy 与模拟 ERP 验收。正式待办量自然达到相应批次时，再核对线上表现。

需要在当前审阅规则上预先生成缓存时，在对应运行根目录空闲期间执行以下命令。它只生成对应版本的派生缓存。

## 单条待复核与继续处理

- WorkBuddy 明确输出「需人工复核」且同批其他记录已完成时，保留原结果及记录 ID，循环继续处理其他空项。待复核明细保持排除，即使规则版本更新。清单仍有空白的待复核行时，跳过该清单的整表一键匹配。
- 完全无关的批次不影响本次清单。存在部分重合的未完成批次时，按日志选择原批次全部清单。人工停止和 ERP 写入、入库待核对仍走原恢复流程。
- 复核后先由操作员在 ERP 保存确认的类别。在运行目录的 `data/workbuddy_review_confirmations/<批次ID>.json` 写入记录 ID 与已保存的 ERP 类别，例如 `{"<记录ID>":"普通类"}`。随后在 Web UI 指定原批次全部清单并点击「导入 WorkBuddy 结果」。程序回读核对 ERP 身份和类别，再按原批次的写入模式收尾。原 WorkBuddy 判定和已经完成的入库记录保留。
