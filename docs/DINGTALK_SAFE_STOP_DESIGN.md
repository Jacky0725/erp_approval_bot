# 钉钉安全停止指令与实现

## 已确认边界

- 仅任务发起人和项目管理员可停止审批；其他群成员仍可查询状态和启动审批。
- 只做安全停止，不撤销、不回滚已保存到 ERP 的结果。
- 钉钉不提供强制杀进程、强制关闭浏览器或强制退出 WorkBuddy 的指令。
- 安全停止已实现，所有恢复仅从本机 Web UI 人工核对后启动。

## 指令

| 指令 | 含义 |
| --- | --- |
| 停止审批 | 为当前任务生成停止确认摘要，不立即发送停止信号 |
| 停止审批 <任务编号> | 为指定的当前运行任务生成停止确认摘要 |
| 确认停止 <确认码> | 由同一发起人在同一会话确认停止，确认码2分钟有效且只能消费一次 |
| 取消 | 取消尚未确认的停止草案；不能撤销已经受理的停止请求 |
| 状态 | 显示任务编号、链路、当前清单/批次、阶段及停止进度 |

内部始终绑定完整任务 ID；界面可显示唯一短编号，短编号冲突时拒绝推断。
停止确认与启动确认使用不同操作类型和不同命令，不复用“确认停止”作为启动确认。
任务已结束或已经切换到新任务时，旧确认无效，不得停止新任务。

## 权限

- 发起身份在任务启动前从可信钉钉回调记录，使用企业 ID 与用户稳定 ID，而非昵称。
- 管理员由本机 Web UI「基础设置 → 钉钉 Stream 机器人」配置明确白名单，不自动信任群管理员标志或模型判断。
- 权限在生成草案和确认停止时均检查；生成后被移出白名单的管理员不能继续确认。
- 默认只允许从任务来源群操作；管理员可在配置的管理群操作。第一版不开放私聊停止。
- Web UI/定时任务没有钉钉发起人，因此钉钉端仅管理员可停止。
- 尚未配置管理员时，不给予任何人默认管理员权限；来源群中的任务发起人仍可停止自己的任务。

## 交互

请求后：

```text
待确认停止，任务仍在运行
任务：8f3c9a12d4e6
链路：WorkBuddy
当前阶段：ERP 类别保存及回读
当前清单：SJ202611040001
已保存结果不会撤销。
请本人在本会话2分钟内发送：确认停止 A1B2C3
```

确认后：

```text
停止请求已受理
任务：8f3c9a12d4e6
正在等待当前操作完成并核对结果，不再开始后续操作。
```

必须区分“已受理停止请求”和“任务已停止”。不承诺任意阶段立即停止。
完成后由工作进程明确回报已停止，发送独立的“人工停止”结果通知，不伪装成审批失败或成功。
沿用原简洁摘要风格，增加已保存、待入库、未处理和结果待核对数量。

## 安全停止点

| 所在阶段 | 收到已确认请求后的行为 |
| --- | --- |
| 登录、读取待办、只读查询 | 在下一检查点停止，不开始新的写操作 |
| ERP 一键匹配 | 若请求已经发出，等待响应、回读及状态落盘后停止；已经完成的匹配不回滚 |
| WorkBuddy 尚未投递 | 保留准备文件，不开始投递 |
| WorkBuddy 正在投递 | 完成当前投递核对并保存状态后停止；结果不明则标记待核对，不重发 |
| 等待 WorkBuddy 结果 | 停止本项目等待，保留批次；不强停 WorkBuddy，晚到结果不自动回写 ERP |
| 结果校验、规则判定、检索 | 在检查点退出；已开始的只读调用可等待有界超时，未开始的调用不再发起 |
| ERP 类别保存/审批提交 | 已发出的操作必须完成响应、必要回读和检查点记录，再停止；不开始下一笔 |
| 生成试剂库 | 已发出的生成及核对完成后停止，不开始下一条生成操作 |
| 无响应或结果不明 | 按现有超时处理并标记待核对；不得为满足停止时限而强杀或重试非幂等操作 |

类别保存与生成试剂库不是一个原子事务。本版允许“类别已保存、试剂库待生成”，
显式保留并统计该状态，不为了凑齐整批而继续发起新的写入。

## 状态与恢复

状态区分运行中、停止请求已受理、等待安全停止、已人工停止、结果待核对和已正常结束。
重复停止请求幂等，不额外投递、不重置正在进行的事务。
首次有效停止一旦受理，不支持从聊天撤销，避免并发修改运行意图。

停止请求按完整任务 ID 持久化，不能使用跨任务共用的简单 STOP 标志。
新任务不会继承旧停止请求；进程重启不自动恢复已停止任务。
若重启后无法确认旧工作进程及 ERP 结果，应显示待核对，而非直接宣告安全停止完成。

原未完成批次必须标记为人工停止，不能被定时任务或普通批次循环悄悄恢复。
第一版不提供群内“继续审批”指令，只通过 Web UI 的受控恢复入口人工核对。
恢复前再次检查 ERP 待办状态、当前类别、规则版本、投递记录和结果文件，仅做经核对的剩余步骤。
禁止重新投递发送结果不明的批次，也禁止重复写入已确认保存的项目。
重叠的清单范围不能通过另一条审批链路绕过暂停。已经读取范围的全量任务恢复时只使用记录下来的范围，不纳入后来新增的待办。

## 实现位置

- 独立任务控制模块负责持久化请求、权限校验和任务 ID 匹配。
- `dingtalk_stream_bot.py` 解析停止、确认及取消，不直接调用当前 `manager.stop()`。
- `web_runner.py` 接收请求并记录发起身份，将完整任务 ID 传给工作进程。
- `approval_flow.py`、`workbuddy_bridge.py` 与桌面等待循环在明确的安全点查询停止请求。
- 继续通过 `audit_logger.py` 记录请求人、任务、时间、权限结果、受理和实际退出，不记录确认码。
- Web UI 提供独立“安全停止”入口；原紧急强制停止保留在本机 Web UI，操作前需明确确认，不接入钉钉。

## 验收

- 发起人、管理员、普通成员、其他群及私聊的权限矩阵。
- 确认码过期、重复确认、确认期间任务结束或切换任务、管理员被移除。
- 等待结果、投递中、保存中、生成试剂库期间的停止，不重复投递或写入。
- 晚到 WorkBuddy 结果不自动导入；人工停止批次不被定时任务恢复。
- 请求结果不明、程序重启及数据库不可写时不误停新任务、不假报已停止。
- 正常成功/失败通知不回归，人工停止使用独立结果，不触发失败重试。

## 已确认并落实

1. 管理员采用 Web UI 配置 `企业ID/用户ID` 白名单，管理群单独配置；来源群限制、Web UI/定时任务仅管理员可从钉钉停止。管理员默认留空，不自动赋予权限。
2. 允许在“类别已保存、试剂库待生成”的安全点停止并单独报告。
3. 第一版恢复只走 Web UI 人工核对入口，不提供群内继续指令。现有 Web UI 紧急强停保留为单独按钮并增加明确确认，不接入钉钉指令。

## 实现约束

- 控制记录与原任务 ID 存于本地 SQLite，任务发起身份在启动前记录；确认时重新核对权限和任务。
- 工作进程在检查点使用专用中断信号退出，普通 ERP 错误处理与重试不会吞掉该信号。
- WorkBuddy 的人工停止批次保留结果文件、投递状态和检查点，不被准备、导入或循环入口自动接续。
- V1 在类别写入、整单通过、试剂库生成前设安全点；待入库操作单独持久化。
- V1 待入库恢复还需核对当前待办、名称、CAS、序号、类别和稳定页面行 ID。缺少稳定 ID 或结果不明时拒绝自动生成，不假装恢复成功。
- 恢复前核对结构化规则、审批配置、测试模式与 ERP 地址，任一变化都拒绝直接使用旧任务。
- 查询到旧任务仍标记运行但本机已无对应受管工作进程时，显示“结果待核对”，不宣告已安全停止。
- 人工停止是独立结果，正常成功/失败通知不变；停止通知只使用本任务已知的控制统计，不借用上次建议文件的条数。
