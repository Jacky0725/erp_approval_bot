# 钉钉审批指令

在钉钉群中 @机器人后发送以下指令。群成员权限保持现有设置。

| 指令 | 链路与范围 |
| --- | --- |
| 执行审批 | WorkBuddy，本次首次读取的全部待办 |
| 执行审批 SJ202611040001 | WorkBuddy，指定清单 |
| 执行审批V1 | V1，本次首次读取的全部待办 |
| 执行审批V1 SJ202611040001 | V1，指定清单 |
| 状态 | 当前任务、链路、清单号；WorkBuddy 同时显示批次阶段 |
| 帮助 | 指令列表 |
| 停止审批 | 发起停止确认，不立即停止 |
| 停止审批 <任务编号> | 为指定的当前任务发起停止确认 |
| 确认停止 <确认码> | 同一人、同一会话在2分钟内确认安全停止 |

V1 和 WorkBuddy 名称不区分大小写。保留“开始审批”“启动审批”别名，
以及“执行审批 WorkBuddy”显式写法。第一版只接受一个清单号，错误或多余参数不执行。

## 范围与安全

- 全量任务在完成 ERP 登录、首次读取待办后固定清单号；运行中新增清单留待下次任务。
- V1 固定范围不受默认 50 个清单上限截断；每个清单处理前仍核对当前待办状态。
- WorkBuddy 每批最多 20 条试剂，沿用既有恢复、结果校验及写入前核对。
- 沿用当前写入模式和 dry-run 安全开关，命令不修改持久配置。
- WorkBuddy 试运行仅执行单批，不回写 ERP；正式任务循环处理固定范围。
- 已有任务运行时不排队、不切换链路。
- WorkBuddy 客户端投递未启用、程序路径无效或正式写入条件不足时拒绝启动。
- 投递结果不明、结果等待超时、ERP 回写失败时保留批次，不盲目重发。
- 结束通知沿用现有成功/失败摘要，WorkBuddy 任务名称明确标注链路。

## 自然语言对话（已实现，默认关闭）

Stream 仅负责消息传输，理解自然语言需要单独的对话模块。
可以复用项目现有 LLM 服务连接，也可以配置独立服务、模型与 API Key。
不要复用化学信息提取器的提示词，也不让对话模型直接操作 ERP 或桌面。

基础设置的“钉钉机器人 → 自然语言对话”中开启。默认使用主 LLM 连接；
如需独立服务，取消“使用主 LLM 连接”，填写 OpenAI 兼容地址、模型和独立 API Key。
独立密钥保存为 `.env` 中的 `DINGTALK_CHAT_API_KEY`，界面只显示是否已配置。
应先确认群消息允许发送至所选模型服务，再开启功能。

可以发送“帮我处理当前全部待办”“用 V1 处理 SJ202611040001”“现在处理到哪个清单了”。
模型推断不作为真实执行结果；自然语言执行仅生成待确认摘要。
发起人必须在原会话中发送 `确认 XXXXXX`（2分钟有效），才能启动。
`取消` 放弃待确认及正在理解的请求；`清空对话` 还清除上下文；均不会终止运行中任务。
新的自然语言请求会替换上次待确认操作，精确审批指令也会清除待确认操作。

实现边界：

1. 精确指令优先，保留无需 LLM 的启动与查询路径。
2. 其他消息交给 LLM 回答帮助、解释只读状态或生成白名单指令草案。
3. 自然语言要求执行审批时，先展示链路、清单范围、写入模式及一次性确认码；确认后才执行。
4. 确认码绑定发起用户、会话及参数并设置有效期；确认时重新检查任务占用和配置。
5. 对话按群与用户隔离上下文，限制长度、调用频率和超时；不发送凭证、原始日志或不必要的 ERP 数据。
6. LLM 故障不影响精确指令；LLM 无权修改规则、配置、运行命令或自行批准试剂。

默认每人每会话每分钟最多6次模型请求，全局每分钟30次，最多2个并发模型请求。
上下文最多8轮，默认4轮，30分钟不活动失效；不写入磁盘。最多保存128个会话。
精确状态、帮助和审批命令不受模型限流影响。
单条最多2000字，模型回复限长；明显的密钥和密码输入会在提交模型前拦截。
这不是通用 DLP，请勿把任何凭证发到群内。

按会话与钉钉消息 ID 在 `data/dingtalk_state.sqlite3` 中持久化去重，执行审批和确认消息
长期保留，查询和聊天消息保留30天。执行前先记录接收事实；若程序在执行前后崩溃导致结果不明，
不会自动重放。重复消息提示查询“状态”；需要再次执行时，用户须主动发送新的审批消息。
缺少可靠消息标识或无法保存去重记录时，审批指令不执行；只读状态和帮助仍可用。
数据库不保存消息原文、确认码或模型回复。进程内另缓存10分钟回复，最多1024条。

群内启动的任务将结束通知发往启动群；自然语言确认使用原群，并可刷新同群临时回复地址。
Web UI、定时任务及私聊启动使用已配置默认群，或兼容旧版已保存的群绑定。
查询、帮助和聊天不会自动修改默认群；没有可用目标时只记录通知失败，不改发其他会话。
任务启动前保存目标快照，结束时不再读取最新全局群绑定；通知格式、@所有人开关不变。
发送成功以业务回执为准，不把 HTTP 200 直接当作成功。明确限流最多3次尝试，间隔1秒、2秒；
发送超时、5xx等结果不明时不盲目重发或切换通道，避免重复通知。获取令牌的无副作用请求可重试。
临时回复地址已过期时，使用同一任务群的主动发送接口；该备用接口保留 Markdown 摘要，
不再伪造正文 `@all`。已核验的普通群消息请求模型没有所有人提醒参数，因此备用发送时会记录
“摘要已受理但所有人提醒降级”的警告；真实提醒效果仍需群内验收，不能仅凭返回码确认成员收到提醒。

Stream 协议解析与回执继续使用固定版本的钉钉 SDK；本地连接层负责有超时的网关协商、
心跳、指数退避重连、关闭连接和取消旧回调。基础设置区分线程存活与实际连接状态，
同时显示最近连接、最近接收与重连次数。重载先关闭旧连接，再使用最新凭证建立新连接。
正在进行的模型或网络工作可能延迟退出；此时显示正在退出，不并行启动第二个连接。
`data/dingtalk_state.sqlite3` 也保存任务目标及临时回复凭证，不纳入版本管理或产物下载，
请勿公开分享该文件。任务目标无法保存时，任务不会启动。
请勿通过删除数据库来处理异常；删除或回滚数据库会丢失相应去重历史，备份时应将其纳入本地受保护备份。

确认状态在重启后全部作废，需重新请求。审计仅记录会话哈希、动作、链路、清单和启动结果，
不记录自然语言原文、确认码或密钥。尚未接入知识库、文件问答、语音或任意工具执行。

## 后续边界

“停止审批”已实现，只允许任务发起人和配置管理员在授权群使用，私聊不开放。
只有工作进程到达安全检查点并完成退出，才显示“已人工停止”；已保存结果不回滚。
基础设置可配置管理员 `企业ID/用户ID` 与管理群 ID 白名单，默认不配置管理员。
Web UI/定时启动任务没有钉钉发起人，钉钉端只能由管理群中的管理员停止。
未完成任务只从“运行控制 → 人工停止任务”核对恢复，不能通过普通指令或定时任务悄悄接续。
恢复需勾选人工核对并确认，规则、配置或 ERP 环境变化会拒绝恢复；投递或写入结果不明时禁止自动重发。
详细边界见 [安全停止说明](DINGTALK_SAFE_STOP_DESIGN.md)。
