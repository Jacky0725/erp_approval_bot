# 试剂信息链路重构 Codex 执行包

本执行包用于重构“名称清洗 → 身份查询 → 物化信息提取 → 规则判定”链路。它基于 2026-09-10 的代码、配置、缓存和历史运行日志形成，不包含对现有业务规则的擅自改写。

## 建议阅读顺序

1. `01_客观分析与推荐方案.md`：现状证据、问题根因、可选方案和推荐结论。
2. `02_目标架构与数据契约.md`：目标流程、模块边界和核心数据结构。
3. `03_分阶段实施任务.md`：可直接执行的阶段、文件范围、测试和提交边界。
4. `04_验收与回滚方案.md`：质量、性能、安全门槛和回滚条件。
5. `proposed_settings.yaml`：新配置结构草案，不应直接覆盖当前 `config/settings.yaml`。
6. `CODEX_MASTER_PROMPT.md`：交给 Codex 执行整个重构的主提示词。
7. `05_实施状态_20260910.md`：本轮实际完成内容、验证结果与生产切换前的剩余门槛。

## 执行原则

- 每个阶段单独提交，阶段通过验收后再进入下一阶段。
- 默认使用 feature flag 和 shadow mode；未达到质量门槛前，不改变 ERP 写入结果。
- 用户完善后的判定规则 Excel 是规则层的权威输入；本包只定义规则如何消费标准化证据。
- 中文商业网站不进入同步关键路径；它们只能作为可选、异步、可熔断的数据补充。
- LLM 输出不能直接成为事实来源或自动审批依据；所有自动判定必须能追溯到规则和证据。
