# 实施状态（2026-09-10）

## 已完成

### 阶段 0：基线和观测性

- 新增 `EnrichmentMetrics`：可选 JSONL 指标，记录缓存层、provider 状态/耗时/重试、LLM 调用状态/耗时和影子差异；不记录试剂原文或网页正文。
- 新增 `enrichment_benchmark.py`：从人工确认的复核队列构建可复现基准。
- 已生成 `data/benchmarks/confirmed_reagents.json`，包含 254 条去重的人工确认样本。

### 阶段 1：确定性身份解析

- 新增 `ReagentIdentityResolver` 和 `IdentityRecord`。
- 本地解析禁用 LLM 和网络访问，包含 CAS 校验位、审核别名、中文清洗结果、混合物/商品试剂标记和冲突状态。
- 有效但未由本地审核映射确认的 CAS 不会被标记为 `verified`。

### 阶段 2：结构化数据源骨架

- 新增 `chemical_sources` 适配器契约和独立 `PubChemAdapter`。
- 身份查询受控并行；CID 确认后按批次获取基础属性。
- PubChem CID 改为独立的 provider ID，ERP CAS 和规则审计使用的 CAS 保持原值，不再以 CID 覆盖。
- 尚未把旧 `ChemicalSearcher` 删除或替换，确保现行链路可回退。
- 新增可选 NIST WebBook 补充适配器，仅解析带标签的沸点、闪点；CompTox 在未配置 API key 时明确返回 `disabled_missing_credentials`，不发起网络请求。

### 阶段 3：字段级证据

- 新增 `EvidenceResolver`、`EvidenceItem`、`ResolvedProperties`。
- 统一温度单位；区分 `false`、`unknown`、`conflict`；保留来源和冲突。
- 新增本地 `SupplierSdsAdapter`：只解析 ERP 已提供的 SDS 文本，不访问供应商网站；闪点、沸点及危险性描述以最高来源优先级进入影子证据。
- LLM 补缺入口默认关闭，只接受可信来源文本和缺失字段；无法在输入中定位的 evidence span 会丢弃对应结果。

### 阶段 4：规则追踪

- `RuleEngine.classify_resolved_properties()` 已接受标准化字段输入。
- 输出规则文件 SHA-256 版本、证据引用和身份/证据冲突警告。
- 旧 `classify()` 接口仍保持兼容。
- 新增 `rule_workbook_validator.py`，在回传 Excel 被接入前检查必需工作表/列、未知类别、重复 rule ID/threshold ID、优先级冲突和阈值运算符。当前正式规则已通过校验（17 类别、77 条启用规则、423 个示例、3 个阈值）。

### 阶段 5：影子接入

- 新增默认关闭的 `EnrichmentV2`。
- 当且仅当 `enrichment_v2.shadow_mode: true` 时，流程会额外计算 V2 结果并记录比较数据；不修改建议、不写 ERP。
- 新增 `enrichment_shadow_report.py`，从 JSONL 指标生成影子对比、provider 和 LLM 日报。
- 管理界面总览新增“新链路影子运行”面板，显示影子/正式开关、对比数量、一致率、provider 调用和异常数。
- 页面级影子调用已改为批量身份解析和批量物性取证；单条接口仍保留兼容。

### 阶段 6：中文别名后台回填

- 新增 `chinese_alias_backfill.py`，按需使用 Chemsrc、ChemicalBook 查询中文名称或别称。
- ChemicalBook 中文名称先走其中文 `Search.aspx` 入口；未命中时才回退英文入口。Chemsrc 保持其支持中文关键词的搜索接口。
- 查询复用旧查询器的主机限流、重试与熔断；503、超时或无结果不会阻塞前台审批流程。
- 仅生成 `config/name_alias_candidates.xlsx` 的 `pending` 候选，绝不自动写入 `config/name_aliases.yaml`。混合物、身份冲突和未解析条目不参与回填。

- 已生成首份影子报告，但当前日志为 0 条真实样本，尚不能用于验收：`data/reports/enrichment_shadow_report.md`。

## 建议的最小影子配置

```yaml
enrichment_v2:
  enabled: false
  shadow_mode: true
enrichment_metrics:
  enabled: true
  jsonl_path: data/logs/enrichment_metrics.jsonl
```

这段配置只会生成对比指标，不会写入 ERP。启用前请合并到当前 `config/settings.yaml`，不要覆盖其他已修改配置。
