# Codex 总执行指令

你是独立技术审查者和实现者。请对当前 reagent-approval-bot 项目执行证据驱动的整体优化，纳入 Web UI 重构。按本目录 README、01–07 文档执行；AGENTS.md 与用户当前指令优先。

## 开始方式

先读当前 Git 状态、AGENTS.md、本包分析/架构/阶段/验收文档，以及现有补全 V2 执行包状态。对比 evidence/baseline.json 的哈希、接口与字段；本包使用旧快照，代码可能已改变。列出已解决、仍存在、新出现的问题，不重复实现已有工作。

不要读取或输出真实 .env 密钥，不覆盖未提交修改。不要 reset --hard、清理未跟踪文件或自动 stash 用户工作。需要备份时把源代码差异和未跟踪源码保存至本地私有位置，不把凭证、真实数据或含敏感信息的配置 diff 放进可分享执行包。

## 目标和范围

1. P0 建立隔离环境、行为/接口/DOM 基线。
2. P1 验证并修复写入结果、恢复与持久化的已确认问题。
3. P2 保持行为，减少业务与 Web 桥接的重复和职责混杂。
4. P3 在隔离实例捕获页面，形成有截图证据的 UI 审查。
5. P4 保留现有技术栈、导航、模板字段和设计 token，实施请求可靠性、表格/表单/反馈和窄屏改善。
6. P5 完成回归、安装包资源检查、文档及交付。

按 05_PHASE_TASKS.md 的依赖推进。每阶段交付可评审的小批次；通过相应验收后继续，不以“已给建议”代替实现。不要为了拆分而拆分；没有证据的问题跳过并记录理由。

## 插件与 skills

按 04_SKILLS_AND_SOURCES.md 使用现有能力。用户已允许搜索并自行安装相关插件/skills，但必须按实际可用工具核验来源、必要性与安装结果，不伪造安装命令或连接状态。优先复用 Product Design 审查能力和项目 Playwright；不强制 Figma、图像生成、前端框架或云端发布。

## 必须保留

- browser_bot 旧入口、web_app:app、现有 API 与 form 字段、DOM ID。
- 当前模板布局/partials、dashboard.js、dashboard.css 的基础结构；新内部文件需兼容资源打包。
- rule_engine 决策入口、规则候选人工晋升、LLM 隔离和 audit_logger 审计职责。
- 现有补全 V2 的在建代码、影子门控和旧链路回退，不批准生产切换。
- 密码留空保留、运行中配置门控、人工复核约束，以及已有下载路径保护和任务互斥。

## 授权边界

可直接执行：只读审查、临时合成数据验证、保持行为和接口兼容的重构、针对已确认缺陷的修复、相关测试和文档。

先完成具体变更草案与影响分析，再确认：改变审批规则/自动通过条件、改变写入结果的既有业务语义、改变外部数据/接口/操作流程、生产数据迁移/删除、引入大型框架、远端部署或真实 ERP 操作。不能通过“优化”名义扩大范围。待确认事项不阻塞其他独立且已授权工作。

不启动真实审批、同步上传、程序更新、钉钉发送或规则晋升。源码开发浏览器使用 headed；不要改正式安装版既有无头策略。UI 验证必须先隔离 lifespan 后台任务及网络副作用，不能仅依赖 dry-run。

## 每阶段必须报告

问题证据 → 修改及兼容影响 → 测试命令与结果 → 仍有的风险 → 下一阶段。更新 07_EXECUTION_STATUS.md，状态使用未开始/进行中/已验证/待确认/阻塞；测试未运行或视觉未验证时不得标为已验证。

最后提供变更摘要、文件、实际验证证据、回退说明和未完成项。不要承诺无基准的性能提升，不用历史报告替代当前验证。
