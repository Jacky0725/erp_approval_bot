# reagent-approval-bot 整体重构分阶段方案

日期：2026-09-10  
基线提交：`0bb865a`  
范围：整个项目，包括 ERP 自动化、审批编排、规则、证据补全、写入、持久化、审计、后台任务、Web UI、测试和 Windows 交付。

## 总体原则

- 不以文件过大为理由重写；先证明错误、耦合或维护成本，再做最小拆分。
- 保留 `src/browser_bot.py` 旧入口、`web_app:app`、现有 API、表单字段、DOM ID、配置键和 Excel 列。
- `rule_engine.py` 继续拥有规则解析与决策；`audit_logger.py` 继续拥有审批审计；页面写入仍由 `approval_writer.py` 完成。
- V2 补全链路的模式切换由独立改动管理；本重构保留当前工作区设置，不覆盖并行开发内容。
- 每阶段单独测试、单独评审、可单独回退。真实 ERP、审批规则、数据迁移和外部接口变化必须另行确认。

## 阶段依赖

```text
P0 基线与隔离
 ├─ P1 执行与数据安全
 │   ├─ P2 ERP 会话和页面读取
 │   └─ P3 审批编排与页面写入
 ├─ P4 规则、证据和人工复核
 ├─ P5 后台任务、审计和可观测性
 └─ P6 Web UI
       ↓
P7 模块收敛与性能验证
       ↓
P8 全量回归、打包和真实环境验收
```

P2、P4、P5、P6 可在 P1 完成后按独立小批次推进；P7 必须等行为边界稳定后进行。

**解决问题**

建立可信起点，防止把已有改动、历史失败或外部服务副作用归因于重构。

**涉及模块**

Git 工作区、pytest 配置、测试 fixture、Web UI 隔离预览、配置加载路径。

**具体任务**

- 记录提交、未提交文件、API/配置/Excel/DOM 契约和关键文件哈希。
- 审查测试是否会触发 ERP、网络、钉钉、同步、更新或生产文件。
- 使用临时目录和合成数据建立隔离 UI 验证；禁止导入后自动启动后台任务。
- 建立修改前的全量非 ERP 测试结果。

**兼容与验证**

不改生产行为。对比旧入口、配置键、API、模板字段；运行全量非 ERP 测试。

**回退**

仅新增基线资料和测试工具，可独立删除；不涉及数据恢复。

**当前状态**

已完成。基线为 478 passed、1 deselected；UI 隔离环境已建立。

## P1：执行结果、文件写入与恢复安全

**解决问题**

避免明确空写入结果被视为成功、回调失败后整段重放、Excel 写入中断破坏旧文件、规则晋升部分成功后无法收尾。

**涉及模块**

`approval_batch_state.py`、`erp_session.py`、`excel_exports.py`、`review_queue.py`、`rule_maintainer.py`、`audit_logger.py`。

**具体任务**

- 明确 `attempted/handled/failed/deferred` 状态含义。
- 保留 legacy `None`/缺省返回兼容，显式空集合保持为空。
- 业务回调开始后出错停止会话重放，保留回调前登录重试。
- Excel 使用同目录临时文件完成后替换；锁定目标生成唯一备用文件。
- 规则已发布但候选状态未保存时，允许幂等重试收尾。
- 隔离不同运行目录的审计日志 handler。

**兼容与验证**

Excel 列、文件位置和返回结构保持。故障注入覆盖序列化中断、文件锁定、同秒备用输出、部分晋升、回调前后错误。

**回退**

按模块撤销该阶段补丁；无需迁移数据。回退会重新引入已确认风险，应在回退记录中明确。

**当前状态**

已完成实现；两项执行语义调整已经用户确认。相关回归通过。

## P2：ERP 会话、登录、页面打开与读取可靠性

**解决问题**

验证会话失效、登录重定向、加载遮罩、分页移动、详情切换和读取稳定性；避免把页面未变化当作翻页成功或继续在失效会话中操作。

**涉及模块**

`erp_session.py`、`reagent_page.py`、`ui_waits.py`、`erp_api_client.py`、`erp_api_discovery.py`。

**具体任务**

- 为登录成功、登录失败、重定向回登录页、应用壳超时定义可判断结果。
- 统一分页移动证据：页码变化或表格签名变化；无法取得两者时失败关闭。
- 区分“最后一页”“按钮不可见”“点击后未移动”“页面错误”。
- 详情读取前验证清单号或行身份，防止读取上一条详情。
- API 读取与页面读取保持相同身份键；发现冲突时进入人工复核，不自动修正正式数据。
- 只在真实 DOM 样本或可复现 fixture 证明问题时调整选择器。

**兼容与验证**

保留旧方法签名，通过内部结果对象或 helper 提升判断。增加 Playwright 合成 DOM 测试、页面切换/分页故障测试；真实 ERP 仅做授权后的 headed dry-run。

**回退**

新 helper 可回退至旧实现；保留失败截图和日志格式兼容。

**当前状态**

已完成代码级修正。待办分页必须取得页码或表格签名变化；登录导航和应用壳验证失败会在业务回调前受控重试；详情页必须读取到与选中待办一致的清单号，否则停止后续处理。相关定向测试通过；未访问真实 ERP。

## P3：审批编排、批次状态与真实页面写入

**解决问题**

确保建议生成、可写候选、页面写入、保存校验、失败重读、重试耗尽和自动通过之间的状态一致，避免重复审批和部分成功被误报。

**涉及模块**

`approval_flow.py`、`approval_writer.py`、`approval_batch_state.py`、`write_failure_diagnostics.py`、`approval_suggestion_metrics.py`。

**具体任务**

- 绘制并固化单条/分页/全待办状态机及终态定义。
- 将纯决策、候选筛选、写入调用、保存验证和恢复步骤分成内部小函数；旧入口保持。
- 每次写入关联稳定工作键、attempt 号和结果；结果未知时不得自动重试修改请求。
- 页面保存后必须读取确认；确认失败时停止自动通过并进入人工核对。
- 对 dry-run、disabled、multi_page、generate_library 分别验证不可写/可写边界。
- 自动通过继续 fail closed：分页、未匹配、人工复核、写入失败或状态未知任一存在均阻断。

**兼容与验证**

不改变置信度阈值、分类或 AUTO_PASS 条件，除非另行确认。使用 fake page/writer 验证重复调用、部分成功、延迟项、重读定位和重试上限。

**回退**

保留旧入口适配层；每个抽取批次可独立回退。真实写入验证前始终 dry-run。

**当前状态**

核心安全边界已完成：显式空 handled 不再误终态；已确认保存但页面收尾失败保持终态并阻断自动通过，不再重复写；保存点击后确认异常作为“结果未知”进入人工复核并停止本轮；指定行操作不再回退点击其它行。P3 定向 100 项测试通过；真实 ERP 回读仍待授权环境验收。

## P4：规则、身份、证据、LLM 与人工复核

**解决问题**

保证身份冲突、证据冲突、缺失字段、LLM 兜底和规则优先级的边界清楚，并可追溯到最终处置。已确认的“未知类”例外统一进入 ERP 写入候选，不再进入人工复核。

**涉及模块**

`rule_engine.py`、`rule_workbook_validator.py`、`reagent_identity.py`、`evidence_resolver.py`、`enrichment_v2.py`、`chemical_sources/`、`chemical_searcher.py`、`llm_extractor.py`、`review_queue.py`、`rule_maintainer.py`。

**具体任务**

- 建立规则工作簿加载、版本、优先级、阈值和冲突的契约测试。
- 将 false、unknown、conflict 保持为不同状态，禁止缺失值被当成否定证据。
- 身份冲突、CAS/名称冲突、混合物和低可信 LLM 结果统一进入复核原因。
- V2 继续 shadow；比较旧/新链路的类别、证据覆盖和高风险召回，不直接接管。
- 规则候选只写 pending；晋升只处理人工 approved，且先运行工作簿验证。
- 审查 `chemical_searcher.py` 中可证明的 provider 重复，再抽取至适配器；保留旧 facade。

**兼容与验证**

除经业务确认的“未知类自动写入”外，正式规则 Excel 不改。使用临时复制的规则簿、固定样本和冲突样本测试；报告规则哈希和差异。后续分类变化仍先提交差异清单等待确认。

**回退**

V2 开关保持原值；旧 `classify()`、旧搜索链路和候选文件格式保留。

**当前状态**

进行中。已统一规则运行时与工作簿校验器对 `enabled=on` 的解释。2026-09-20 经业务确认，所有最终判定为“未知类”的建议统一取消人工复核并以置信度 1.0 进入 ERP 写入候选；流程入口会覆盖旧记忆、检索、LLM 或 V2 携带的旧复核标志。`config/rules_structured.xlsx` 与迁移器已同步，候选晋升条件未改，已有人工复核队列数据未迁移或删除。规则/流程定向 179 项测试通过，全量 622 passed、1 deselected；真实 ERP 写入仍待授权环境验证。

## P5：后台任务、配置、审计与可观测性

**解决问题**

统一任务 run ID、决定、写入尝试、最终结果和通知之间的关联；降低 `web_runner.py` 对日志文本解析的依赖；确保配置保存和任务生命周期一致。

**涉及模块**

`web_runner.py`、`automation_worker.py`、`scheduler.py`、`dingtalk_stream_bot.py`、`dingtalk_notifier.py`、`audit_logger.py`、`stage_logger.py`、`config/settings.yaml`。

**具体任务**

- 定义内部 `RunState/RunEvent` 数据结构，先在进程内使用；外部 API 返回保持兼容。
- 为每次任务分配 run ID，并把规则版本、目标清单、dry-run、决定和写入结果关联。
- 日志文本继续提供给 UI；状态摘要优先读取结构化状态，不依赖英文字符串匹配。
- 配置更新保持原子写入、运行中拒绝修改和秘密不回显。
- 调度、钉钉和 Web 手动触发复用同一任务互斥与参数校验。
- 通知失败不改变审批执行结果，只记录独立失败状态。

**兼容与验证**

API 字段只允许向后兼容新增；不改变现有 endpoint。测试并发启动、停止、进程崩溃、重启恢复、回调失败、通知失败和状态文件损坏。

**回退**

保留旧日志解析作为兼容回退；结构化状态文件可忽略，不做生产数据库迁移。

**当前状态**

部分完成。审批建议已写入结构化决定事件（输入身份、规则版本、依据、置信度和复核标记），保存/页面结果写入结构化执行事件；Windows 日志句柄写后释放。任务管理器的运行日志、状态文件和待办缓存现在严格使用实例 `root_dir`，避免多实例串线。run ID 和 UI 摘要摆脱文本解析仍待后续小批次。

**涉及模块**

重点为 `approval_flow.py`、`chemical_searcher.py`、`web_runner.py`、`approval_writer.py`；是否拆分由调用图和变更热点决定。

**具体任务**

- 统计调用关系、重复函数、测试覆盖、运行阶段耗时、网络调用数和重复查询。
- 优先抽取纯模型与纯转换：写入结果、建议构建、provider 结果、运行状态摘要。

**回退**

## 完成定义

整个项目重构只有同时满足以下条件才可称为完成：

1. P0–P7 的已确认问题完成实现与回归，没有未解释的测试退化。
2. 审批规则、API、配置、Excel 和 UI 契约的变化均有用户确认或保持兼容的证据。
3. 审批决定、写入尝试、校验和最终结果可由 run ID 追溯。
4. 模拟验证与真实 ERP 验证明确分开；未授权真实写入不执行。
5. Windows 安装包资源和启动流程完成验证。
6. 文档包含运行、升级、回退、已知限制和未验证项。
