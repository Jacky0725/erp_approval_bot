# Web UI 专项方案

## 工作目标

维持密集型业务操作台，让操作员能快速回答：正在处理什么、当前是否可能写入、哪条需要复核、证据在哪里、失败后如何继续。不是增加营销式首页或用装饰性大卡片替换业务表格。

本轮未截图，下面是待执行的设计规格和假设。进入 UI 改造前必须在隔离环境捕获当前八页，并标注每条发现对应的页面、状态和截图。没有截图证据时只能提出候选问题。

## 页面范围：保留原导航和 URL

| 页面 | 优化重点 | 必须保留 |
| --- | --- | --- |
| 总览 `/` | 当前任务、待复核数量、异常及下一步入口；健康/影子数据区分未加载、无样本、错误和正常 | 当前健康、补全 V2 影子面板与状态来源 |
| 运行 `/run` | 清晰展示选中清单、执行范围、写入风险；运行中一致禁用；停止请求与已停止分开 | 清单选择、原 action、写入模式和服务端安全门控 |
| 建议 `/suggestions` | 列表与证据详情关联；长文本可读，未知与否定值区分 | 类别、置信度、原因、规则/来源证据和原字段 |
| 复核 `/review` | 保留筛选分页与未保存输入；保存后行定位；错误落在对应行 | LLM 辅助建议不得自动预选为确认结果 |
| 记忆库 `/memory` | 搜索、分页、编辑、冲突提示一致；批量操作明确范围 | 原保存/删除/同步语义与已有确认机制 |
| 设置 `/settings` | 按连接、执行、安全、调度、维护分组；高级项逐步展开；保存反馈明确 | 字段 name，密码留空保留原值，运行中拒绝改配置 |
| 产物 `/artifacts` | 类型、时间、名称清晰；无产物和读取失败不同 | 原下载边界与真实文件路径映射 |
| 日志 `/logs` | 过滤、自动滚动与暂停查看协同；保留当前阅读位置 | 任务上下文和日志文本脱敏要求 |

分组和折叠是候选布局，默认不移动业务步骤、不新增自动执行按钮。改变导航或操作流程需先提供具体前后对照。

## 交互规范

1. 将读取中、正常空数据、网络失败、过期数据、任务失败分开显示。失联保留最后已知结果并明确标注，不能清空成“0 条”或更新成“成功”。
2. 状态读取采用单次在途请求或完成后再调度；增加合理超时和有界退避。页面隐藏时降低读取频率，回到前台及时刷新。具体间隔用基线验证，避免无依据全面改成 WebSocket/SSE。
3. 查询使用序号或取消机制防旧响应覆盖新筛选；读请求取消不代表服务端修改已撤销。POST/DELETE 超时不能自动重试，需读取实际结果或提示结果未知。
4. 编辑中不覆盖字段、不抢焦点、不清除选中项；需要刷新列表时先保护 dirty 状态。保留后端互斥，不能仅依赖按钮禁用。
5. HTTP 失败、非 JSON、超时、业务拒绝有一致处理，错误信息不回显敏感原始响应。
6. 文本优先 textContent；动态 HTML 逐项审计转义；来源链接验证 http/https 等允许协议。禁止凭 innerHTML 关键字做无证据漏洞判定。

## 视觉规范

- 复用现有蓝灰主题、CSS variables 和中文字体栈；不因重构自行更换品牌色。
- 面板圆角不超过 8px，边框明确、阴影克制；胶囊状态标签可保持其语义形状。
- 将常用字号、行高、控件高度补成少量语义 token；表格、按钮和表单密度一致。不得机械替换每个像素值。
- 主操作、次操作、危险操作语义清晰；不能只用颜色区分；可用文字标签描述当前写入风险。
- 表格仅在 `.table-wrap` 横向滚动；不得用 body overflow-x:hidden 掩盖被裁剪的表单或按钮。
- 窄屏优先保证操作可达、标签可读和表格可滚动，不默认将所有数据表改成卡片。
- 保留键盘焦点可见、输入 label、语义表头、导航当前项和必要的状态播报；轮询不应反复播报整个页面。

## 验收规格

- 八页至少在 1440×900、390×844 拍摄；总览/运行/复核另测 1280×800、360×800 和 200% 缩放。
- 检查表格正常、空状态、长名称、长证据、多页、失败、超时、编辑中刷新和无真实影子样本状态。
- 检查页面 scrollWidth 与可视宽度及关键控件边界；仅无横向滚动条不能证明未裁切。
- 保存截图并逐张观察；检查 console error、未处理 Promise、资源 404 和重复事件提交。
- 用固定合成数据比较前后状态读取并发数、DOM 更新和请求数量。承诺目标：状态读取最多一个在途；旧响应不覆盖新状态；非重试场景一次用户提交只产生一次修改请求。
- 以 WCAG 2.2 AA 的焦点不被遮挡、最小目标尺寸等为检查参考，不仅靠截图声称合规。密集控件需核验尺寸或间距例外。

## skills 使用节点

P3 用 Product Design audit 对当前隔离页面做证据审查；P4 针对已有代码目标实施兼容调整。只有用户需要全新视觉方向时才进入 ideate/imagegen；只有用户需要可编辑设计源时才使用 Figma。不要为了调用插件额外创建云端网站。
